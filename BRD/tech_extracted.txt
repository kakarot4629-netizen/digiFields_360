1. Architecture Overview
digiField360.ai Salesforce Edition is a managed package (DF360__) deployed on a Salesforce Enterprise org. It follows the same architectural philosophy as digiSFA: Salesforce as the platform of record, Agentforce as the AI backbone, Flutter as the offline-capable mobile client, and Meta WhatsApp Business API as the primary customer communication channel.
The two products (digiSFA and digiField360) are designed to co-exist in the same Salesforce org. They share Named Credentials, the WhatsApp service infrastructure, and the Firebase push notification channel, while operating in separate namespaces (dSFA__ and DF360__) with no object overlap.

11. Co-existence with digiSFA
digiField360 and digiSFA are designed to co-exist in the same Salesforce org without conflict. The following rules govern co-existence:
Concern
Rule
Namespace isolation
All DF360 objects prefixed DF360__; all dSFA objects prefixed dSFA__. No shared custom objects.
Shared Named Credentials
5 Named Credentials (MetaWhatsApp, GoogleMaps, AIService, Razorpay, Firebase) are created once and referenced by both packages.
Shared Apex services
DF360_WhatsAppService references the same sendFromFlow() @InvocableMethod signature as dSFA_WhatsAppService. Built as a separate class to avoid compilation dependency.
Permission Sets
No overlap. A user can hold both DF360_Technician and dSFA_FieldRep if they do both roles (uncommon but possible).
User object
Both products write to custom User fields (dSFA__Territory__c and DF360__Zone reference). No field conflict.
Org limits impact
Combined 34 custom objects (16 dSFA + 18 DF360) against Salesforce Enterprise limit of 800. < 5% utilisation.
